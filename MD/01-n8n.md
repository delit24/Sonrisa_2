# n8n Workflow Terv

## Áttekintés

Az n8n egyetlen workflow-ból áll, amely két fő fázisból épül fel:

| Fázis | Feladata |
|---|---|
| Feed feldolgozás | RSS feedek beolvasása, Gemini elemzés, Supabase mentés |
| Alert dispatch | Feldolgozatlan eventek lekérése, user preferenciák egyeztetése, értesítés küldés |

- **Ütemezés:** Minden 15 percben fut a teljes workflow
- **Előny:** Egyszerűbb kezelés, egy helyen minden, MVP-hez elegendő

---

## Teljes Flow diagram

```
Schedule Trigger (15 perc)
  ↓
Feed URL Lista (Code node)
  ↓
Loop Over Feeds
  ↓
RSS Feed Read
  ↓
Duplicate Check (Supabase: source_url már szerepel-e?)
  ↓ (csak új cikkek mennek tovább)
Gemini Flash — elemzés és strukturálás
  ↓
Parse Gemini Response (Code node)
  ↓
Is Relevant? (IF node)
  ↓ (csak releváns cikkek)
Supabase Insert Event
  ↓
Get User Preferences (WebAPI endpoint)
  ↓
Match Events to Users (Code node)
  ↓
Is Email Channel? (IF node)
  ├── igen → Send Email
  └── nem → Send Slack Message
  ↓
Log Notification Sent (Supabase processed_notifications)
  ↓
Mark Event as Processed (Supabase events UPDATE)
```

## Node-ok részletesen

### 1. Schedule Trigger
- Típus: `Schedule Trigger`
- Ütemezés: minden 15 percben
- Konfiguráció: `*/15 * * * *`

### 2. Feed URL Lista
- Típus: `Code` node
- RSS feed URL-ek listája — itt módosítható, nem hardcode-olva a workflow többi részében
- Output: feed URL-ek tömbje

Kezdő feed lista:
```
https://feeds.bbci.co.uk/news/rss.xml
https://feeds.reuters.com/reuters/topNews
https://rss.nytimes.com/services/xml/rss/nyt/World.xml
```

### 3. Loop Over Feeds
- Típus: `Split In Batches` node
- Batch size: 1 — feed-enként egyenként dolgozza fel
- Az RSS Read node csak az első elemet dolgozza fel, ezért szükséges a loop

### 4. RSS Feed Read
- Típus: `RSS Feed Read`
- URL: `{{ $json.feedUrl }}` — az előző node-ból veszi
- Output: cikk lista (title, link, pubDate, contentSnippet)

### 5. Duplicate Check
- Típus: `Supabase` node — getAll
- Tábla: `events`
- Szűrő: `source_url = {{ $json.link }}`
- Ha talál eredményt: IF node kihagyja
- Ha nem talál: tovább a Gemini node-ra

### 6. Gemini Flash — elemzés
- Típus: `HTTP Request` node
- Model: `gemini-2.0-flash`
- Endpoint: `https://generativelanguage.googleapis.com/v1beta/models/gemini-2.0-flash:generateContent`
- Auth: Query paraméter — `key = {{ $env.GEMINI_API_KEY }}`

**Prompt:**

```
You are a news classification assistant. Analyze the following news article and return a structured JSON response.

Article title: {{ $json.title }}
Article content: {{ $json.contentSnippet }}
Source URL: {{ $json.link }}
Published at: {{ $json.pubDate }}

Classify the article into exactly ONE of these categories:
- breaking_news: wars, terrorist attacks, political crises, major accidents
- market: stock market, cryptocurrency, economic indicators, company earnings
- natural_disaster: earthquakes, floods, hurricanes, wildfires
- tech: AI developments, cybersecurity, major tech company news

Extract up to 5 relevant keywords from the article (proper nouns, locations, organizations, key terms).
Write a summary in maximum 3 sentences in English.

Return ONLY a valid JSON object, no markdown, no explanation:
{
  "category": "breaking_news|market|natural_disaster|tech",
  "summary": "...",
  "keywords": ["keyword1", "keyword2", "..."],
  "is_relevant": true|false
}

Set is_relevant to false if the article is an opinion piece, advertisement, or not genuinely newsworthy.
```

### 7. Parse Gemini Response
- Típus: `Code` node
- Gemini válasz JSON-ból kinyeri az adatokat
- Backtick-es markdown wrapper eltávolítása (Gemini néha így adja vissza)
- Az eredeti RSS adatokat (source_url, title, pubDate) hozzáfűzi

### 8. Is Relevant?
- Típus: `IF` node
- Feltétel: `is_relevant == true`
- False ág: csendes skip, nem hiba

### 9. Supabase Insert Event
- Típus: `Supabase` node — create
- Tábla: `events`
- Mezők: source_url, source_feed, title, summary, category, keywords, published_at, processed=false, raw_content

### 10. Get User Preferences
- Típus: `HTTP Request` node
- Endpoint: `GET {{ $env.WEBAPI_BASE_URL }}/api/internal/user-preferences`
- Header: `X-Internal-Api-Key: {{ $env.WEBAPI_INTERNAL_KEY }}`

### 11. Match Events to Users
- Típus: `Code` node
- Összeveti az event kategóriáját és kulcsszavait a user preferenciákkal
- Minden match-re egy rekordot ad vissza csatornánként

**Egyeztetési logika:**
```javascript
for (const event of events) {
  for (const user of users) {
    for (const pref of user.preferences) {
      if (pref.category !== event.category) continue;
      if (pref.keyword) {
        const keyword = pref.keyword.toLowerCase();
        const inSummary = event.summary.toLowerCase().includes(keyword);
        const inKeywords = event.keywords.some(k => k.toLowerCase().includes(keyword));
        const inTitle = event.title.toLowerCase().includes(keyword);
        if (!inSummary && !inKeywords && !inTitle) continue;
      }
      // match → csatornánként egy rekord
    }
  }
}
```

### 12. Is Email Channel?
- Típus: `IF` node
- Feltétel: `channel == "email"`
- Igaz ág: Send Email
- Hamis ág: Send Slack Message

### 13. Send Email
- Típus: `Send Email` node
- SMTP credential: environment variable-ből
- Subject: `[Alert] {{ $json.eventCategory }}: {{ $json.eventTitle }}`
- Body: kategória, cím, összefoglaló

### 14. Send Slack Message
- Típus: `Slack` node
- Auth: Bot token (`{{ $env.SLACK_BOT_TOKEN }}`)
- Channel: `{{ $json.destination }}` (pl. `#alerts`)
- Szöveg: kategória badge + cím + összefoglaló

### 15. Log Notification Sent
- Típus: `Supabase` node — create
- Tábla: `processed_notifications`
- Mezők: event_id, user_id, channel

### 16. Mark Event as Processed
- Típus: `Supabase` node — update
- Tábla: `events`
- Feltétel: `id = {{ $json.eventId }}`
- Mezők: `processed = true`

## Környezeti változók (n8n Settings → Variables)

| Változó | Leírás |
|---|---|
| `GEMINI_API_KEY` | Google AI API key |
| `SUPABASE_URL` | Supabase projekt URL |
| `SUPABASE_SERVICE_KEY` | Supabase service role API key |
| `SLACK_BOT_TOKEN` | Slack bot token (`xoxb-...`) |
| `SMTP_USER` | SMTP felhasználónév / feladó email |
| `WEBAPI_BASE_URL` | .NET WebAPI alap URL |
| `WEBAPI_INTERNAL_KEY` | Belső API key az n8n → WebAPI kommunikációhoz |

---

## Hibakezelés

| Hiba | Kezelés |
|---|---|
| Gemini API nem válaszol | Retry 3x, majd skip — az elem processed=false marad, következő körben újra próbálja |
| Supabase insert sikertelen | n8n beépített error log |
| SMTP hiba | Retry 2x, majd folytatja a többi csatornával |
| Slack channel nem található | Log, folytatja a többi csatornával |
| Duplikált source_url | Csendes skip, nem hiba |

---

## Duplikáció védelem — összefoglalás

Kétszintű védelem:

1. **Feed szinten:** `source_url` UNIQUE index — ugyanaz a cikk nem kerül be kétszer
2. **Értesítés szinten:** `UNIQUE(event_id, user_id, channel)` — ugyanarról az eventről ugyanannak a usernek ugyanazon a csatornán csak egyszer megy értesítés
