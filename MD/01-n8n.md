# n8n Workflow Terv

## Áttekintés

Az n8n két önálló workflow-ból áll:

| Workflow | Feladata | Ütemezés |
|---|---|---|
| `feed-processor` | RSS feedek beolvasása, Gemini elemzés, Supabase mentés | Minden 15 percben |
| `alert-dispatcher` | Feldolgozatlan eventek lekérése, user preferenciák egyeztetése, értesítés küldés | Minden 5 percben |

> **Miért két külön workflow?**
> A feed feldolgozás és az értesítés küldés különböző ütemezést és hibakezelést igényel. Ha az értesítés küldés hibázik, a feed feldolgozás attól még futhat. Könnyebb debugolni és monitorozni.

## 1. Workflow: `feed-processor`

### Flow diagram

```
Schedule Trigger (15 perc)
  ↓
RSS Feed Read (loop: minden konfigurált feed)
  ↓
Duplicate Check (Supabase: source_url már szerepel-e?)
  ↓ (csak új cikkek mennek tovább)
Gemini Flash — elemzés és strukturálás
  ↓
Supabase Insert — events tábla
```

### Node-ok részletesen

#### 1. Schedule Trigger
- Típus: `Schedule Trigger`
- Ütemezés: minden 15 percben
- Konfiguráció: `*/15 * * * *`

#### 2. RSS Feed Read
- Típus: `RSS Read`
- Feed URL-ek (konfiguráció szintjén megadva, nem hardcode-olva):
  ```
  https://feeds.bbci.co.uk/news/rss.xml
  https://feeds.reuters.com/reuters/topNews
  https://rss.nytimes.com/services/xml/rss/nyt/World.xml
  https://feeds.bloomberg.com/markets/news.rss
  ```
- Output: cikk lista (title, link, pubDate, description, content)

> **Megjegyzés:** Az RSS feed URL-ek egy n8n environment variable-ben vagy egy külön konfigurációs node-ban legyenek tárolva, ne a workflow kódjában hardcode-olva. Ez lehetővé teszi, hogy admin felületről később bővíthető legyen.

#### 3. Duplicate Check
- Típus: `Supabase` node — SELECT
- Lekérdezés: `SELECT id FROM events WHERE source_url = '{{ $json.link }}'`
- Ha talál eredményt: `Stop and Error` node vagy `IF` node — az adott elem kihagyása
- Ha nem talál: tovább a Gemini node-ra

#### 4. Gemini Flash — elemzés
- Típus: `HTTP Request` node (Gemini REST API)
- Model: `gemini-2.0-flash`
- Endpoint: `https://generativelanguage.googleapis.com/v1beta/models/gemini-2.0-flash:generateContent`

**Prompt:**

```
You are a news classification assistant. Analyze the following news article and return a structured JSON response.

Article title: {{ $json.title }}
Article content: {{ $json.description }}
Source URL: {{ $json.link }}
Published at: {{ $json.pubDate }}

Classify the article into exactly ONE of these categories:
- breaking_news: wars, terrorist attacks, political crises, major accidents
- market: stock market, cryptocurrency, economic indicators, company earnings
- natural_disaster: earthquakes, floods, hurricanes, wildfires
- tech: AI developments, cybersecurity, major tech company news

Extract up to 5 relevant keywords from the article (proper nouns, locations, organizations, key terms).
Write a summary in maximum 3 sentences in English.

Return ONLY a valid JSON object, no markdown, no explanation:
{
  "category": "breaking_news|market|natural_disaster|tech",
  "summary": "...",
  "keywords": ["keyword1", "keyword2", "..."],
  "is_relevant": true|false
}

Set is_relevant to false if the article is an opinion piece, advertisement, or not genuinely newsworthy.
```

- `is_relevant: false` esetén az elem kihagyásra kerül — IF node szűri

#### 5. Supabase Insert
- Típus: `Supabase` node — INSERT
- Tábla: `events`
- Mezők:
  ```json
  {
    "source_url": "{{ $json.link }}",
    "source_feed": "{{ $json.feedUrl }}",
    "title": "{{ $json.title }}",
    "summary": "{{ $gemini.summary }}",
    "category": "{{ $gemini.category }}",
    "keywords": "{{ $gemini.keywords }}",
    "published_at": "{{ $json.pubDate }}",
    "processed": false,
    "raw_content": "{{ $json.description }}"
  }
  ```

## 2. Workflow: `alert-dispatcher`

### Flow diagram

```
Schedule Trigger (5 perc)
  ↓
Supabase — feldolgozatlan eventek lekérése (processed = false)
  ↓
WebAPI — aktív user preferenciák lekérése
  ↓
Code node — egyeztetés (event vs preferenciák)
  ↓ (minden match-re)
IF: email csatorna aktív?
  ↓ igen
Send Email (SMTP)
  ↓
IF: slack csatorna aktív?
  ↓ igen
Send Slack message
  ↓
Supabase — processed_notifications INSERT
  ↓
Supabase — events UPDATE (processed = true, ha minden usernek ment)
```

### Node-ok részletesen

#### 1. Schedule Trigger
- Ütemezés: minden 5 percben
- Konfiguráció: `*/5 * * * *`

#### 2. Supabase — feldolgozatlan eventek
- Típus: `Supabase` node — SELECT
- Lekérdezés:
  ```sql
  SELECT * FROM events
  WHERE processed = false
  ORDER BY fetched_at ASC
  LIMIT 50
  ```

#### 3. WebAPI — user preferenciák
- Típus: `HTTP Request` node
- Endpoint: `GET /api/internal/user-preferences`
- Auth: API key header (belső kommunikáció, nem JWT)
- Response struktúra:
  ```json
  [
    {
      "userId": 1,
      "preferences": [
        { "category": "breaking_news", "keyword": null },
        { "category": "market", "keyword": "bitcoin" }
      ],
      "channels": [
        { "type": "email", "destination": "user@example.com" },
        { "type": "slack", "destination": "#alerts" }
      ]
    }
  ]
  ```

#### 4. Code node — egyeztetés logika

```javascript
const events = $('Supabase Events').all().map(i => i.json);
const users = $('WebAPI Preferences').first().json;

const matches = [];

for (const event of events) {
  for (const user of users) {
    for (const pref of user.preferences) {

      // Kategória egyezés
      if (pref.category !== event.category) continue;

      // Kulcsszó szűrés (ha van megadva)
      if (pref.keyword) {
        const keyword = pref.keyword.toLowerCase();
        const inSummary = event.summary.toLowerCase().includes(keyword);
        const inKeywords = event.keywords.some(k =>
          k.toLowerCase().includes(keyword)
        );
        if (!inSummary && !inKeywords) continue;
      }

      // Match! Minden aktív csatornára létrehozunk egy rekordot
      for (const channel of user.channels) {
        if (!channel.isActive) continue;

        matches.push({
          eventId: event.id,
          userId: user.userId,
          eventTitle: event.title,
          eventSummary: event.summary,
          eventCategory: event.category,
          channel: channel.type,
          destination: channel.destination,
        });
      }
    }
  }
}

return matches.map(m => ({ json: m }));
```

#### 5. Send Email
- Típus: `Send Email` node
- SMTP konfiguráció: environment variable-ből
- Subject: `[Alert] {{ $json.eventCategory }}: {{ $json.eventTitle }}`
- Body:
  ```
  Hello,

  A new alert has been triggered based on your preferences.

  Category: {{ $json.eventCategory }}
  Title: {{ $json.eventTitle }}

  Summary:
  {{ $json.eventSummary }}

  ---
  Alert System — Manage your preferences at [frontend URL]
  ```

#### 6. Send Slack Message
- Típus: `Slack` node
- Authentication: Bot token (environment variable: `SLACK_BOT_TOKEN`)
- Resource: Message
- Operation: post
- Channel: `{{ $json.destination }}`
- Text:
  ```
  *[{{ $json.eventCategory | upper }}]* {{ $json.eventTitle }}

  {{ $json.eventSummary }}
  ```

#### 7. Supabase — processed_notifications INSERT
- Típus: `Supabase` node — INSERT
- Tábla: `processed_notifications`
- Mezők:
  ```json
  {
    "event_id": "{{ $json.eventId }}",
    "user_id": "{{ $json.userId }}",
    "channel": "{{ $json.channel }}"
  }
  ```

#### 8. Supabase — events UPDATE
- Típus: `Supabase` node — UPDATE
- Tábla: `events`
- Feltétel: `id = {{ $json.eventId }}`
- Mezők: `{ "processed": true }`

## Környezeti változók (n8n)

Az alábbi értékek n8n environment variable-ként legyenek tárolva, ne a workflow-ban:

| Változó | Leírás |
|---|---|
| `SUPABASE_URL` | Supabase projekt URL |
| `SUPABASE_SERVICE_KEY` | Supabase service role API key |
| `GEMINI_API_KEY` | Google AI API key |
| `SLACK_BOT_TOKEN` | Slack bot token (`xoxb-...`) |
| `SMTP_HOST` | SMTP szerver host |
| `SMTP_PORT` | SMTP port (pl. 587) |
| `SMTP_USER` | SMTP felhasználónév |
| `SMTP_PASSWORD` | SMTP jelszó |
| `WEBAPI_BASE_URL` | .NET WebAPI alap URL |
| `WEBAPI_INTERNAL_KEY` | Belső API key az n8n → WebAPI kommunikációhoz |
| `RSS_FEED_URLS` | Vesszővel elválasztott RSS feed URL lista |

## Hibakezelés

| Hiba | Kezelés |
|---|---|
| Gemini API nem válaszol | Retry 3x, majd Skip — az elem `processed = false` marad, következő körben újra próbálja |
| Supabase insert sikertelen | n8n beépített error workflow — log és alert az admin emailre |
| SMTP hiba | Retry 2x, majd log a `processed_notifications`-be `failed` státusszal (opcionális mező) |
| Slack channel nem található | Log, folytassa a többi csatornával |
| Duplikált source_url | Csendes skip, nem hiba |

---

## Duplikáció védelem — összefoglalás

Kétszintű védelem van beépítve:

1. **Feed szinten:** `source_url` UNIQUE index a Supabase `events` táblában — ugyanaz a cikk nem kerülhet be kétszer
2. **Értesítés szinten:** `UNIQUE(event_id, user_id, channel)` index a `processed_notifications` táblában — ugyanarról az eventről ugyanannak a usernek ugyanazon a csatornán csak egyszer megy értesítés
